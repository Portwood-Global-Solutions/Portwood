HTML font merge tags - scratch validation, 15 October 2026

Tag syntax: {%font:<asset-key>:<revision-prefix>}, used as a CSS declaration inside a
quoted inline style attribute. Assets generates a canonical 16-character revision prefix;
longer prefixes through the full 64-character key are accepted. Resolution requires one
unambiguous verified or retired face. It never chooses a mutable latest-family revision.

Implemented through the shared HTML extractor and PDF wrapper. Body-level inheritance is
retained; nested tags choose another exact face. Fonts remain pinned in the versioned source
on save/reopen. Running headers and footers are supported without page-counter tags. A section
combining custom fonts with page counters fails explicitly because that rendering path
flattens markup into unbound CSS content. Font tags are not stylesheet macros or image URLs.

Assets exposes each verified active face's tag, a Copy font tag button, and an HTML example.
The live control and successful copy message were verified in Chrome. No browser security
settings were changed. Existing image tags and the Canvas font-binding contract remain intact.
